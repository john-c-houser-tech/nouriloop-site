Install Compromise Checker

Version 0.1.2, a pre-release. Expect rough edges.

What you need

  • A machine of its own. It holds keys that act as an administrator on every server it checks, so it shouldn't be one of them, or a machine used for anything else. A small cloud server does well, and so does a spare PC.
  • Ubuntu 24.04 or 26.04, or Rocky Linux 9 or 10, on an x86 machine. Close relatives, such as Linux Mint, aren't supported yet, and the installer stops with a message.
  • At least 1 GB of memory and 5 GB of free disk. On a new 1 GB server, right after install, 285 to 485 MB of memory was in use on the whole machine and the install had added 430 to 600 MB of disk. Checking servers and making PDF reports use more while they run.
  • An internet connection, and a login that can use sudo.

The line to paste

Open a terminal on that machine and paste this, then press Enter. Click it once to select all of it.

(d=$(mktemp -d) && trap 'rm -rf "$d"' EXIT && curl -fsSL https://github.com/john-c-houser-tech/compromise-checker/releases/download/v0.1.2/install.py -o "$d/install.py" && echo "8bc8989552356ef0aff29e0bcc291e5e53b53b7fbe919ff422857bccef022a5e  $d/install.py" | sha256sum -c - && sudo python3 -I "$d/install.py")

Copy it from this page, and only from here. The line downloads the installer and checks it against the hash in the line. That hash is all that protects the installer, since the file comes from the same place as the rest of the release. So check that your browser's address bar shows nouriloop.com/work/compromise-checker/install/ before you copy.

If it says curl: command not found, which can happen on Ubuntu Desktop, run sudo apt install curl and paste the line again.

What happens next

  1. The installer checks the release's signature before it runs anything from it. It refuses any other release, or one signed by anyone else.
  2. It looks for other use of the machine and stops if it finds some, unless you tell it to go on. Nothing has been changed by then.
  3. It asks whether people will use the tool from other computers. If not, it answers only on the machine itself, for a browser there. If so, it needs a web address of its own, and the machine has to be reachable from the internet.
  4. It asks, one at a time, whether to turn off SSH password logins, turn off root logins over SSH, and hold off addresses that keep failing to log in. Enter means no.
  5. It installs the tool, turns on a firewall and automatic security updates, makes the SSH changes you agreed to, turns sleep off so a daily check isn't missed, and starts the web interface. Installing takes a minute or two on most systems and about three minutes on Rocky 10.
  6. It gives you a link for making the first account. The link works once, within an hour. If you lose it or it runs out, sudo /usr/local/sbin/compromise-checker-link makes a new one, and the installer prints that command too.

The full list, with what each step changes, is in the installation guide.

After that: add a server, keep a copy of the evidence key, and read the security and privacy policy. The page shows you where.

How this release was checked

Each of the four systems was installed from the real download, on a new server, with and without a web address (using Let's Encrypt's test certificates), and then restarted to see that the tool came back. The line was the one above, with the installer's questions answered ahead of time. The installer was also tried with a wrong hash, and refused. To check the release yourself, see the release page, where every file is listed with its hash, and how to rebuild it and compare.

This is a pre-release, so something may not work. If it doesn't, please contact us, or report it on GitHub. A security problem goes through GitHub's private reporting.
